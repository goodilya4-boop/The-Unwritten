# Architecture

## Platform

- Minecraft: 1.21.1
- Loader: NeoForge
- Java: 21
- Build system: Gradle
- Mappings: Parchment

## Mod

- Mod ID: the_unwritten
- Mod name: The Unwritten
- Base package: com.theunwritten

## Core principles

1. Игровая логика не должна зависеть от клиентского рендера.
2. Постоянные данные персонажа хранятся отдельно от вычисляемых характеристик.
3. Системы должны иметь минимальное количество прямых зависимостей друг от друга.
4. Игровые правила сначала проектируются, затем реализуются.
5. Каждая крупная система должна иметь собственную документацию.

## Character data

- Attributes хранит базовые STR, DEX, END, INT, WIL и PER.
- CharacterStats вычисляет производные характеристики из атрибутов.
- CharacterResources хранит текущие ресурсы персонажа.
- Potential задаёт мягкий ориентир развития, а не жёсткий предел.
- CharacterData объединяет постоянное состояние персонажа.

## Attribute modifiers

Используется одна каноническая модель AttributeModifier.

Модификатор имеет стабильный id, целевой атрибут, amount, операцию и ResourceLocation source.

Порядок вычисления фиксирован:

Base → ADDITION → MULTIPLY_BASE → MULTIPLY_TOTAL

Формула:

effective = (base + additions + base × sum(multiplyBase)) × (1 + sum(multiplyTotal))

Мультипликативные значения являются дельтами: 0.25 означает +25%.

Модификаторы одной операции сначала суммируются, поэтому результат не зависит от порядка их регистрации.

source идентифицирует систему или контент, которому принадлежат модификаторы. Он не является идентификатором конкретного ItemStack; жизненный цикл конкретного экземпляра предмета будет управляться системой экипировки.

## Item data components

Компонент attribute_modifiers хранит модификаторы, предоставляемые предметом. Он является декларацией данных предмета, а не механизмом экипировки.

Система экипировки отвечает за определение экипированных предметов, применение их модификаторов, удаление ранее применённых модификаторов и предотвращение дублирования.

## Testing

Математика атрибутов должна тестироваться отдельно от Minecraft-рендера и игрового UI. При добавлении новых операций сначала добавляются тесты на формулу и порядок применения.
